## Context

运营分类页面当前为每个剧目提供“上移 / 下移”按钮，并在每次点击后调用现有分类整体替换接口。数据层已经以有序 slug 数组保存分类，因此本次只需要改进页面交互，无需改变持久化模型或同步协议。

## Goals / Non-Goals

**Goals:**

- 通过单一、明确的拖拽手柄让剧目卡片随指针位置实时上下重排。
- 一次拖拽只在放下后提交一次最终顺序，避免移动过程中产生多次网络请求。
- 支持鼠标和触屏 Pointer Events，并允许键盘用户在手柄上通过上下方向键排序。
- 保存失败时恢复拖动前的顺序，避免页面显示与服务器状态不一致。

**Non-Goals:**

- 不修改分类 API、数据库表、业务服务器同步格式或 dirty 状态规则。
- 不引入第三方拖拽依赖。
- 不支持跨分类拖动；跨分类成员调整仍使用“添加 / 管理”弹窗。

## Decisions

### 使用 Pointer Events 实现列表内拖拽

拖拽只从 `drag_indicator` 手柄启动，但 pointer capture SHALL 由不会换位的分类列表容器持有。移动过程中使用指针当前纵坐标与目标卡片中线比较，通过 DOM `insertBefore` 实时移动当前卡片并刷新序号。Pointer Events 同时覆盖鼠标、触控笔和触屏，比原生 HTML Drag and Drop 的触屏行为更一致，也无需新增依赖。

不能由手柄或卡片自身持有 pointer capture：卡片通过 `insertBefore` 换位时会发生 DOM 移除和重新插入，浏览器可能立即释放该元素的 pointer capture 并触发 `lostpointercapture`，从而错误结束拖拽。列表容器在整个排序过程中保持挂载和位置稳定，可以持续接收指针事件直到实际 `pointerup` 或 `pointercancel`。

### 放下后提交完整有序快照

拖动过程中只改变本地 DOM；`pointerup` 后从列表 DOM 收集 slug 顺序，并复用 `PUT /admin/featured-categories/{category}` 一次性持久化。如果顺序未变化则不请求。保存成功后更新前端分类状态并高亮运营分类同步按钮，保存失败则按照拖动前的 slug 数组恢复 DOM。

### 手柄同时作为键盘排序控件

手柄使用可聚焦按钮，并响应 `ArrowUp` / `ArrowDown`。键盘移动同样先实时调整 DOM，再调用相同的持久化流程。这样可以移除占空间的独立上下按钮，同时保留无鼠标操作能力。

### 使用 FLIP 动画衔接 DOM 换位

每次真正交换位置前记录所有卡片的视觉纵坐标（First），完成 DOM 插入后读取新布局坐标（Last），再通过 Web Animations API 从坐标差值平滑过渡到零位移（Invert / Play）。动画保持在约 160ms，并在连续拖动时从当前视觉位置重新计算，避免快速跨越多项时闪跳。系统启用 `prefers-reduced-motion: reduce` 时跳过动画并立即换位。

## Risks / Trade-offs

- [快速连续拖动可能与尚未完成的保存请求重叠] → 保存期间禁用当前分类的拖拽手柄，响应完成后恢复。
- [拖动时页面可能意外选择文字或触发滚动] → 手柄设置 `touch-action: none`，启动拖动后阻止默认指针行为；靠近视口边缘时主动小步滚动页面。
- [卡片 DOM 换位导致拖拽被误判为松手] → 由稳定的列表容器而不是被移动的手柄持有 pointer capture，只有真实的 `pointerup` / `pointercancel` 才结束操作。
- [快速拖动造成换位动画堆积或回弹] → 新换位先读取当前视觉位置并取消上一段排序动画，再从该位置启动短动画；减少动态效果偏好下禁用动画。
- [网络失败后本地顺序与服务端不同] → 保留拖动前的完整顺序并在失败时恢复 DOM，不修改客户端分类状态。
