## Why

运营分类目前只能在单部剧详情中勾选“最热 / 最新 / 独家”，分类总览是只读的，且分类内顺序由更新时间隐式决定。运营人员无法在一个页面完成选剧、移除和人工排序，也没有独立于单剧内容同步的运营分类发布动作。

## What Changes

- 新增固定运营分类“推荐”，与“最新 / 最热 / 独家”使用相同的人工编排能力。
- 将运营分类关系改为有序剧单；每个分类可直接添加、移除剧并持久化明确顺序。
- 重做运营分类管理页：每个分类展示有序剧单，添加时弹出完整剧列表并支持选中 / 反选，保存后可继续调整顺序。
- 保留剧详情页的分类勾选入口，并使其与新的有序剧单数据兼容；从剧详情新增分类成员时默认追加到分类末尾。
- 新增受同步权限保护的运营分类专用管理接口，将四个分类及其有序剧 slug 快照显式同步到业务服务器。
- 跟踪运营分类是否有尚未同步的实际修改：有修改时高亮同步按钮，同步成功或内容未变时使用普通样式。
- 运营分类编排不再依赖单剧 `sync_status` 或单剧同步 payload 发布。

## Capabilities

### New Capabilities

- `featured-category-curation`: 固定运营分类（推荐、最新、最热、独家）的有序存储、后台选剧 / 移除 / 排序与管理 API。

### Modified Capabilities

- `business-server-sync`: 增加运营分类快照的专用 HLS 管理端同步动作及业务服务器线协议，并从单剧同步 payload 中移除运营分类。

## Impact

- 数据库：`drama_featured_categories` 增加“推荐”枚举与分类内排序字段，并在启动时迁移已有分类关系。
- 后台：`/admin/featured-categories` 页面、运营分类管理 JSON 接口、剧详情分类勾选逻辑。
- 同步：新增 HLS 管理端触发接口和业务服务器 `/sync/featured-categories` 接收协议；继续复用现有业务同步地址、API key、超时与 `can_sync` 权限。
- 测试与文档：覆盖有序替换、成员增删、参数校验、同步 payload 和失败响应。
